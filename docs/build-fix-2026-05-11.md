# Vercel Build & Runtime Fix - May 11, 2026

## Issues Resolved
1. **TypeError: (0, e.headers)(...).get is not a function**:
   - Cause: Synchronous `headers()` calls in Next.js 16 or old Clerk versions.
   - Fix: Upgraded `@clerk/nextjs` to `^7.3.3`. Ensured all `auth()` calls are awaited.
   - Note: If this persists, verify that `CLERK_SECRET_KEY` is set in Vercel, as initialization errors can sometimes trigger this.

2. **DATABASE_URL Missing / Build Failures**:
   - Cause: Next.js attempted to pre-render pages during the build phase without DB access.
   - Fix: Added `export const dynamic = 'force-dynamic'` to all affected routes.
   - **CRITICAL**: The `DATABASE_URL` must be set in the Vercel Project Settings (Environment Variables) for the *runtime* to work. Currently, the server logs show it is missing at runtime.

3. **Middleware & Subdomain Routing**:
   - Cause: Middleware naming and old `req.headers.get("host")` pattern.
   - Fix: Renamed to `middleware.ts` and updated to use `req.nextUrl.hostname`.

## Implementation Details
- **package.json**: Updated `@clerk/nextjs` to `^7.3.3`.
- **db/index.ts**: Improved resilience and added warnings for missing environment variables.
- **middleware.ts**: Modernized for Clerk v7 and Next.js 16.
- **app/p/[subdomain]/page.tsx**: Added error handling for database queries.
